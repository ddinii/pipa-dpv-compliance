# P2-R09 — 사고 시점 일치 검증 (신규 Rule, v1.1)

- **입력:** 사고 기록의 F2-05 (`incidentDate`), 통지문의 F2-08 (`notice_incident_time`).
- **GREEN:** 같은 시점이면 GREEN (ISO 8601 표기가 달라도 동일한 UTC 시각은 일치).
- **YELLOW:** 두 시점이 다르거나 값·시간대가 불명확한 경우. 확인이 필요하다.
- **N/A:** 통지문 부재가 명시적으로 확인된 경우.
- **RED 미사용:** 입력된 두 문서 간 일관성을 점검하며 위반 여부나 통지 기한을 판단하지 않는다.
- **연결:** 각 사고의 `hasNotificationNotice`로 연결된 통지문만 비교한다.
- 기존 P2-R03, F2-05/F2-08 Fact, 온톨로지 v1.0을 변경하지 않는다.
- 기존 18개 Rule을 보존하고 1개의 v1.1 Rule을 추가한다.

## 날짜만 적힌 경우

Extractor는 날짜만 적힌 원문("2026년 8월 14일")을 `2026-08-14T00:00:00+09:00`으로 채운다.
그래서 한쪽이 날짜만 있으면 두 값이 "다르게" 보인다.

| 경우 | 판정 | 확인 항목 | 사유 |
|---|---|---|---|
| 한쪽만 날짜, **같은 날** | YELLOW | `incident_time_precision` | 날짜는 일치하지만 한쪽 문서에 시각이 없어 시각까지는 비교할 수 없음 |
| 한쪽만 날짜, 다른 날 | YELLOW | `incident_time_mismatch` | 시점이 다름 |
| 둘 다 날짜만, 같은 날 | GREEN | | 일치 |

- 판정은 위 YELLOW 규칙(값이 불명확)을 그대로 따른다. 사유와 확인 항목만 "다르다"와 구별한다.
- 날짜는 **날짜만 적힌 쪽의 시간대**로 비교한다.
- 실제 자정(00:00) 사고와 "시각 미기재"는 저장된 값으로 구별할 수 없다. 그래서 판정을 GREEN으로
  올리지 않는다. 날짜만 같은 경우를 GREEN으로 볼지는 Rule 담당자 결정 사항이다.
- 예: held-out `h1-shop-hacking`(사고 기록 "오전 3시 20분경", 통지문 "8월 14일")은 이 경우다.
